# 커밋 메시지 규칙

[Conventional Commits](https://www.conventionalcommits.org/ko/v1.0.0/)를 참고해서 한글 태그로 바꿔 씁니다.

## 형식

```
[태그] 제목

본문 (선택)

꼬리말 (선택)
```

## 태그

| 태그 | 언제 | Conventional Commits |
|---|---|---|
| `[추가]` | 새 기능 | `feat` |
| `[수정]` | 버그 수정 | `fix` |
| `[개선]` | 기존 기능 향상 (UI, 성능, 사용성) | `feat` / `perf` |
| `[리팩터]` | 동작은 같고 코드 구조만 변경 | `refactor` |
| `[삭제]` | 코드, 파일, 기능 제거 | - |
| `[테스트]` | 테스트 추가, 수정 | `test` |
| `[문서]` | README, 주석, 문서 | `docs` |
| `[설정]` | 빌드, 의존성, CI, 환경 설정 | `build` / `ci` / `chore` |
| `[완료]` | 마일스톤 마무리 | - |

헷갈릴 때는 이렇게 고릅니다.
- 사용자가 새로 할 수 있는 게 생겼다 → `[추가]`
- 원래 되던 게 더 좋아졌다 → `[개선]`
- 원래 되어야 하는데 안 됐다 → `[수정]`
- 사용자가 느끼는 변화가 없다 → `[리팩터]`, `[테스트]`, `[설정]`, `[문서]`

## 규칙

1. 제목은 50자 이내로 쓰고, 끝에 마침표를 붙이지 않습니다.
2. 제목은 "~함", "~했음"보다 "~ 추가", "~ 변경"처럼 짧게 끝냅니다.
3. 제목과 본문 사이는 한 줄 비웁니다.
4. 본문에는 **무엇을, 왜** 바꿨는지 씁니다. "어떻게"는 코드에 있습니다.
5. 커밋 하나에는 한 가지 일만 담습니다. 기능 추가와 버그 수정을 섞지 않습니다.

## 예시

```
[설정] GitHub Actions CI 추가

- push와 PR마다 단위 테스트와 디버그 빌드를 자동 실행
- 테스트 리포트를 Actions 아티팩트로 업로드
```

```
[수정] core-ktx 버전을 1.17.0으로 변경

1.19.0은 AGP 9.1 이상과 compileSdk 37 이상을 요구해서
현재 AGP 8.13.2 / compileSdk 36 환경에서 빌드가 실패함
```

```
[추가] 결제일 계산 로직 추가

월말 결제일 보정 규칙 포함 (1/31 결제 → 2월은 말일)
```

```
[완료] M0 프로젝트 세팅 완료
```

## 템플릿 사용

저장소의 `.gitmessage`를 커밋 템플릿으로 등록해 두면 `git commit`(`-m` 없이)을 실행할 때 위 안내가 편집기에 뜹니다.

```bash
git config commit.template .gitmessage
```
